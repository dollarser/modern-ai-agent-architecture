# 1.1.0 发布验收

范围：前几轮未提交的书稿、协议与开源项目核查、AgentHost 双语言安全修复，以及本轮可靠性改进。不包含原工作区 `videos/` 试验内容。此前审查记录反映各自时间点，新能力以本记录及当前示例 README 为准。

## 本轮实现

- 同一进程/事件循环内，同存储路径与 Run 共享互斥；两个 Host 并发请求只执行一次 Tool、一次最终答案生成。
- 消息幂等键持久化；重复请求复用 Task/Run 和答案，内容冲突拒绝。取消/异常回写状态，显式恢复使用原 Context 和 Run。
- 不同 Session 可并发；相同 Session 按序处理。历史上限为 0 不传历史。
- 最终答案持久化，完成回放不调用模型；答案生成失败不重跑已完成 Tool；交付 Hook 失败不推翻已持久化的完成事实。
- 可信回执核对入口拒绝本地活跃调用和无证据结果；核对后补录确定结果并继续原 Run，不重新派发该步骤。
- 错误码使用稳定分类，原始自由文本保留为原因。

## 验收与边界

- Python 新增 7 项可靠性测试，全书当前数量见 `specs/book/11-current-baseline.md`；TypeScript 增加对应场景。
- 本地全量 Python、全部 TypeScript build/test、基线、源码摘录、内部链接、全部 Mermaid、MkDocs strict、Markdown lint 和 diff 检查是发布前必过项。
- 远程 Python 3.10/3.11/3.12、Node 18/20/22、文档构建与 Pages 部署以目标提交的 GitHub Actions 终态为准；本地运行结果不能替代远程矩阵。
- 教学实现仍不提供多进程事务、数据库租约、Outbox、OS 沙箱、真实 Provider/MCP Transport 或 Helix 设备验收。完整 JSON Schema 与下游回执验真由生产 Adapter 提供。
- 新快照与旧格式不保证兼容。保留旧数据，显式迁移或核对后创建新 Run，不能删除未知派发记录来绕过对账。

外链检查只覆盖维护中的正文和根入口，历史设计/审查快照不作为外链维护清单；站内链接和源码摘录独立校验。GitHub 当前仓库 `blob/main` 源码链接按待发布检出校验，避免新文件在合并前被误判为 404。远端连接失败保留为传输错误，不当作成功；自动 HTTP 成功只接受最终 2xx；OpenAI 三个公开文章/新闻入口对 CLI 返回 403，已通过官方页面检索实际打开并核对正文，记录在 `specs/book/link-evidence.json`。该记录只对 HTTP 403 有效，30 天过期，输出仍保留 403，不覆盖 404 或传输失败。站点的 `release.json` 提供版本和提交，部署后核对。

## 发布方式

独立工作树、功能分支与 PR，经检查后合并 main；创建新 `v1.1.0`，不移动 `v1.0.0`。Pages 发布书稿，Release 提供对应标签的静态站点归档和完整源码归档。
